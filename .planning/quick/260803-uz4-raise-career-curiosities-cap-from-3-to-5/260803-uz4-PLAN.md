<objective>
Let students pick up to 5 career curiosities instead of 3, and tell them what is
happening when they reach the cap instead of silently dimming the remaining chips.

Source: user feedback while testing the deployed app on mobile — "the instructions say
pick up to three, but I would like to pick more… maybe it could be 'pick up to 5'? I
think it would allow for more secondary interests."
</objective>

<context>
**Downstream impact: none.** `curiosities` is write-only today. It is collected in
character creation, written to `students.self_map` (jsonb, unconstrained) by
`lib/persistence/provision-student.ts:93`, and never read — verified zero references in
`lib/scoring/`, `data/`, `app/api/`, and every component except the picker itself. The
dashboard types it in `StudentData` but renders `perceived_strengths`, not curiosities.

So raising the cap cannot affect scoring or results quality. The value is forward-looking:
a richer `self_map` for the Session 3+ Claude career analysis that will read it.

**Second defect, from the same screenshot.** At the cap the eight unselected chips render
at `opacity: 0.5` with `--cq-text-muted`, taps are silently ignored
(`curiosities-picker.tsx:48`), and the "(N remaining)" hint *disappears* — it is gated on
`remainingPicks > 0` at line 66. The student is left with washed-out buttons that do
nothing and no explanation. Raising the cap does not fix this.

**Not in scope:** the mid-session "What do you think you're naturally good at? Pick up to
3" picker (`components/selfmap/self-map-capture.tsx:177`). That 3 is analytically load-
bearing — `SelfVsMeasured` compares those picks against the top measured strengths.
</context>

<tasks>

### Task 1 — Raise the cap and explain it

**Files:** `components/character/curiosities-picker.tsx`, `lib/types/student.ts`

**Action:**
- `MAX_SELECTIONS` 3 → 5. The heading copy interpolates it already, so "Pick up to 5"
  follows for free.
- Keep the "(N remaining)" hint, and add the missing at-cap branch: "(5 of 5 — tap one to
  swap)". Both live in one `aria-live="polite"` element so a screen reader announces the
  cap rather than leaving it silent.
- Raise disabled-chip opacity 0.5 → 0.65. These chips are not permanently disabled — the
  student must read them to decide what to swap out, so they need to stay legible.
- Update the `SelfMap.curiosities` comment in `lib/types/student.ts` from `0-3` to `0-5`.

**Verify:** `npx tsc --noEmit`, `npm run lint`

**Done:** Six chips cannot be selected; the fifth selection shows the swap hint.
