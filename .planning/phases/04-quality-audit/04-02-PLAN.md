<!-- Error boundary pattern from research (Next.js 16 docs) -->

Route-level error.tsx signature (Next.js 16.2.0+):
```typescript
'use client'
export default function Error({
  error,
  unstable_retry,
}: {
  error: Error & { digest?: string }
  unstable_retry: () => void
}) { ... }
```

Key: Use `unstable_retry` NOT `reset`. The `unstable_retry` re-fetches data and re-renders the segment.

Section-level SectionErrorBoundary:
- React class component (React 19 still supports class components for error boundaries)
- Props: `{ children: ReactNode; name: string; fallback?: ReactNode }`
- State: `{ hasError: boolean; error: Error | null }`
- getDerivedStateFromError + componentDidCatch (silent per project convention)
- handleRetry resets state to re-render children

Existing UI reference for error styling:
- `components/ui/persistence-banner.tsx` — reference for error fallback color/layout
